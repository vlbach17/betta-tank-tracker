# design-sync notes — betta-tank-tracker

## Repo shape
- This is an app repo (`betta-tank-tracker`, Vite + React), not a published component library. `package.json` has no `main`/`module`/`exports`, so the converter runs in **synth-entry mode** (no dist library build) — the JS entry is generated by re-exporting every `.tsx`/`.jsx` file under `srcDir`.
- No Storybook. Package shape.

## Scope
- User chose "reusable UI only": Avatar, BackLink, Button, Icon, IconButton, Input, NavChips, Notice, ParameterTile, RangeField, RangeToggle, StatusDot, StatusPill.
- Excluded (app-specific screens, not design-system components): Dashboard, Overview, Settings, ParameterHistory, LogTest, MiniHistoryChart.
- `componentSrcMap` explicitly lists all 13 target names with real repo paths (`src/components/<Name>.tsx`) — this is what limits "components" (preview/doc treatment) to just those 13, since with no shipped `.d.ts` the "authoritative" export list is empty and only `componentSrcMap` entries populate it.

### Why `srcDir` points at `.design-sync/entry-src/`, not `src/components/`
Entry synthesis (no packaged library build exists, so the converter re-exports every `.tsx`/`.jsx` file under `srcDir` to build the JS bundle) does NOT consult `componentSrcMap` — it blindly includes every file in `srcDir`, scoped components or not. Pointing `srcDir` straight at `src/components/` pulled in the excluded screens too (`LogTest.tsx`, `Dashboard.tsx`, etc.), which import `src/lib/parameters.ts` → `src/lib/supabase.ts` for real (not type-only) — and `supabase.ts` **throws at module-evaluation time** if `VITE_SUPABASE_URL`/`VITE_SUPABASE_PUBLISHABLE_KEY` aren't set (they aren't, in this build context). Since the whole bundle is one IIFE, that throw aborted the entire script before ANY component got assigned to `window.BettaTankTracker` — `package-validate.mjs` failed all 13 with `[BUNDLE_EXPORT]`.

Fix: `.design-sync/entry-src/` holds 15 one-line re-export stubs (`export * from '../../src/components/<Name>'`), one per scoped component **plus** `HardnessUnitProvider.tsx` and `TempUnitProvider.tsx` (needed as `cfg.provider` targets — see below). `srcDir` points here instead of `src/components/`, so entry synthesis only ever sees these 15 files. Each stub's relative import resolves straight to the real file, so the real file's OWN internal relative imports (`../lib/format`, `./Icon`, etc.) resolve completely normally — only the *entry synthesis* file list is curated, nothing about component behavior or grouping changed. `componentSrcMap` paths are unaffected (they resolve relative to the repo root, independent of `srcDir`).
- **If a new reusable component should join the scope later**: add both a `componentSrcMap` entry AND a matching stub file in `.design-sync/entry-src/`. Only adding one or the other will not work correctly.
- **If `HardnessUnitProvider`/`TempUnitProvider` need to change** (renamed, moved, or the provider chain changes), update their stub files too.

## Providers
- `ParameterTile` calls `useTempUnit()`/`useHardnessUnit()`, both of which **throw** outside their providers.
- `BackLink`, `NavChips`, `ParameterTile` all use `react-router-dom` (`Link`/`NavLink`), which throws outside a Router context.
- Fix: `extraEntries: ["react-router-dom"]` merges its exports into `window.BettaTankTracker`, and `cfg.provider` wraps every preview in `MemoryRouter > TempUnitProvider > HardnessUnitProvider`.

## CSS
- Styling is Tailwind v4 with CSS-first config (`@theme` block in `src/index.css`, no `tailwind.config.js`). The raw source file only has `@import "tailwindcss"` plus the `@theme` tokens — it is NOT usable as `cssEntry` directly, since utility classes (`bg-mist`, `rounded-full`, etc.) only exist after Tailwind's build step compiles them.
- Fix: ran `npm run build` and pointed `cssEntry` at the compiled output (currently `dist/assets/index-D39HGZXj.css`).
- **Re-sync risk**: this filename is content-hashed by Vite and WILL change on every `npm run build`. Before every re-sync, re-run the build and update `cssEntry` in config.json to the new hashed filename (`ls dist/assets/index-*.css`) before running the converter.
- Fonts (Plus Jakarta Sans Variable, Fira Code, DynaPuff) are imported globally in `src/main.tsx` via `@fontsource*` packages, not from any file under `src/components/`. The compiled `dist/assets/index-*.css`'s own `@font-face` rules point at Vite's hashed `/assets/...woff2` paths, which the converter could not copy/rewrite into `fonts/` (`[FONT_DANGLING]` for most of them — only 3 tiny data-URI-inlined weights survived). Fix: `cfg.extraFonts` points directly at the canonical `@fontsource` package CSS files instead (`node_modules/@fontsource-variable/plus-jakarta-sans/index.css`, `node_modules/@fontsource/fira-code/{400,500,600}.css`, `node_modules/@fontsource/dynapuff/400.css` — matching exactly what `src/main.tsx` imports). These resolve to real files inside `node_modules/@fontsource*/files/`, which do get copied. Went from 53 broken font refs to 53 real font files in `ds-bundle/fonts/`.
- `--font-mono` in `src/index.css` used to end in unshipped Windows-only fallback names (`"Cascadia Mono"`, `"Segoe UI Mono"`, `Consolas`) after the real shipped font (Fira Code). Per user decision (2026-09-08), removed those three — the stack is now `"Fira Code", ui-monospace, "SF Mono", monospace`. This was a small edit to the real app source (`src/index.css`), not just a design-sync artifact — already reflected in the app itself.

## Required one-time machine setup: self-referencing node_modules junction
The converter resolves the package's own directory (`PKG_DIR`) as `<node-modules>/<pkg>` when no `--entry` flag is passed (and we deliberately don't pass one, since passing `--entry` would short-circuit synth-entry mode down to a single file). Since this repo IS the package (not an installed dependency of itself), `node_modules/betta-tank-tracker/` doesn't exist by default and the build fails with `ENOENT ... node_modules\betta-tank-tracker\package.json`.

Fix (already done, but this doesn't survive `npm ci`/a fresh clone/`node_modules` being wiped — recreate it any time the build fails with that ENOENT):
```powershell
New-Item -ItemType Junction -Path ".\node_modules\betta-tank-tracker" -Target "."
```
This is gitignored (it's inside `node_modules/`) and machine-local, like the `.design-sync/node_modules` fork symlink the base SKILL.md describes for a different purpose.

## Re-sync risks
- `cssEntry`'s hashed filename goes stale on every `npm run build` — re-detect it (`ls dist/assets/index-*.css`) and update `config.json` before every re-sync.
- The `node_modules/betta-tank-tracker` self-junction (above) must exist before running the converter — recreate it if missing.
- `componentSrcMap` is an allowlist by design here (not just override entries) — adding a new reusable component later requires an explicit new entry in BOTH `componentSrcMap` AND a stub file in `.design-sync/entry-src/` (see "Why srcDir points at .design-sync/entry-src/" above). Neither alone is sufficient.
- If `src/lib/supabase.ts`'s env-var guard, or any new component's dependency chain, changes to import something that reaches `supabase.ts` (or otherwise throws at module-evaluation time) from one of the 15 files in `.design-sync/entry-src/`, the whole bundle will silently break again with `[BUNDLE_EXPORT]` on every component (not just the offending one) — check `.render-check.json`/validate output for that signature if a future re-sync suddenly fails all components at once.
- **`.design-sync/entry-src/` currently has 14 stub files, not 15** (`HardnessUnitProvider.tsx` is gone — see the 2026-09-16 entry below). Cross-check the actual count against `componentSrcMap` + `cfg.provider` before trusting either as current; this repo has drifted from its own sync scope twice already (`NavChips`, then `HardnessUnitProvider`).

## Converter fixes + full re-sync (2026-09-16)
Claude Design's own project-health check flagged two pre-existing issues in the synced (read-only-in-the-project) source, both fixed here and rolled into a full re-sync:

**1. `fonts/fonts.css` duplicate/dangling `@font-face` blocks.** The converter's font extraction scrapes rules from BOTH the compiled `dist/assets/index-*.css` (`cfg.cssEntry`) AND `cfg.extraFonts`. `cssEntry`'s rules point at Vite's hashed `dist/assets/*.woff2` paths, which never resolve under the converter's containment roots (see the original "CSS" section above) — `extractFonts` still emits those rules with their original, dangling `url()`s instead of dropping them, right next to the REAL, working rule `cfg.extraFonts` provides for the same family. Editing `.ds-sync/lib/*.mjs`/`package-build.mjs` directly turned out to be a dead end for THIS session (background-session worktree isolation blocks edits that resolve, via the machine-local `.ds-sync` junction, back to the shared checkout — see "Machine setup" below) — fixed instead as a **new committed post-process script, `.design-sync/postprocess.mjs`**, run after the normal build and before upload:
  ```sh
  node .ds-sync/resync.mjs --config .design-sync/config.json --node-modules <nm> --out ./ds-bundle --remote <anchor>
  node .design-sync/postprocess.mjs --out ds-bundle
  ```
  It drops any `@font-face` block with zero resolving `url()` (fully dead), then — since a handful of `cssEntry` blocks survive that check because their PRIMARY src is a working base64 `data:` URI even though a secondary `.woff` fallback still points at a dead path — groups the rest by `(family, weight, unicode-range)` and keeps only the "clean" (no `/assets/`, no `data:`) block per group, matching what `cfg.extraFonts` already ships. Went from 54 blocks (many duplicated) to 28 clean ones. **This step is NOT part of `package-build.mjs`/`resync.mjs` — always run it after every build, before every upload**, or the duplication comes back.
- **`_ds_bundle.css`'s own font-face duplication is separate and already handled**: `lib/css.mjs`'s existing `rewriteBundleFontFaces` already drops dead-`url()` blocks from `_ds_bundle.css` specifically (26 dropped on this run) — only `fonts/fonts.css` needed the new postprocess step.

**2. 13 unclassified design tokens.** claude.ai/design's Design System pane classifies each custom property it finds as color/spacing/typography/other, inferred from the value shape; function-valued tokens (gradients, easing curves) and Tailwind v4's own generated custom properties (`--tw-*`, `--default-transition-*`) don't infer cleanly and need a literal `/* @kind <word> */` comment immediately before the declaration. `postprocess.mjs` (same script, second half) injects these into `_ds_bundle.css`: exact names for the 4 hand-authored ones in `src/index.css` (`--gradient-cta-track`, `--gradient-avatar-ring`, `--gradient-hero-wash` → `color`; `--ease-out` → `other`), and prefix-matched for the Tailwind-internal ones (`--tw-*`, `--default-transition-*` → `other`) — **inspecting the real compiled CSS found ~68 distinct `--tw-*` property names** (not a handful), scattered across many individual utility-class rules, not just a root block, so the prefix match annotates every declaration site of every one of them (103 total insertions this run). Pure CSS comments — zero visual effect, confirmed by re-running `package-validate.mjs` and re-reviewing every component's render check after.

**3. Found while re-syncing: `HardnessUnitProvider` no longer exists.** `.design-sync/entry-src/HardnessUnitProvider.tsx` re-exported `../../src/components/HardnessUnitProvider`, but that file is gone — commit "fix: standardize KH/GH on ppm and sync RangeField slider focus" removed the dGH/dKH unit toggle entirely (KH/GH are ppm-only now), so nothing in the app calls `useHardnessUnit()` any more. The stale stub broke the build outright (`[UNRESOLVED_IMPORT]`). Fix: deleted `.design-sync/entry-src/HardnessUnitProvider.tsx` and trimmed `cfg.provider` from `MemoryRouter > TempUnitProvider > HardnessUnitProvider` to `MemoryRouter > TempUnitProvider`. Also fixed the two now-stale `HardnessUnitProvider`/`NavChips` mentions in `.design-sync/conventions.md` (the `readmeHeader` — this was actively telling the design agent to wrap every composition in a provider that no longer exists on the bundle) — per the base skill's rule, edited it in place (not re-authored from scratch) since it already existed, then did the required fresh driver rebuild so the generated `README.md` carries the fix.
- **Re-sync risk**: if hardness-unit display logic ever comes back, it needs a NEW provider stub + `cfg.provider` entry from scratch — nothing to restore, this was a clean removal.

**4. `NavChips` cleanup.** Already gone from `src/components/` and `.design-sync/entry-src/` (see "Machine setup" note above — this repo has now drifted this way twice). This re-sync's anchored diff correctly detected it as `removed` and its 6 remote paths were deleted cleanly (`components/general/NavChips/*`, `_preview/NavChips.{js,css}` — the `.css` delete came back not-found, which is expected and fine: NavChips never had one).

**Machine setup used for this run**: background-session worktree isolation blocks direct edits to `.ds-sync/` and `node_modules/` (both gitignored, and a worktree doesn't check either out) even when explicitly asked to work in the main checkout — the guard resolves symlinks/junctions back to the real shared path and refuses. Rather than mutate the main checkout's shared `node_modules/betta-tank-tracker` self-junction (which would silently break IT for the main checkout), ran `npm ci` fresh inside the worktree for an independent `node_modules/`, then created its own self-junction (`node_modules/betta-tank-tracker` → the worktree root) and a plain junction `.ds-sync` → the main checkout's `.ds-sync` (safe to share read-only; `.ds-sync` isn't mutated by a build, only read). This is exactly why the font/token fix became a new `.design-sync/*` script instead of a `.ds-sync/*` edit — the latter was structurally blocked for this session, and turned out to have a cleaner, git-committable solution anyway.
- Verified via 12/12 components hand-graded `good` against their `_screenshots/review/*.png` (visual spot-check: fonts, colors, gradients, spacing all read correctly after the postprocess + provider-chain trim — nothing here should have changed pixels, and nothing did), `package-validate.mjs` exiting clean both before and after `postprocess.mjs`, and a post-upload `list_files` matching the local build exactly (121 content files + sentinel + anchor).
