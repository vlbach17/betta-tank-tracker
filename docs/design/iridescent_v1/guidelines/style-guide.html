Spunk'sbettabase — iridescent

A style guide for building screens in this system. Spunk's Bettabase is a single-user water-parameter log for one betta aquarium, used from a phone as an installed PWA. The palette is lifted from Spunk himself: royal blue body, teal sheen, violet-to-magenta fin edges, pearl head.

Primary light themePearl ground, white surfaces, slate ink.
Numbers are the contentEvery value, unit, range and timestamp is Fira Code, tabular.
One gradient per screenThe signature appears once — CTA, avatar ring, or chart line.

Non-negotiables

✓The gradient appears exactly once per screen.
✓Numbers, units and timestamps use --font-mono; UI text uses --font-sans at 500–800.
✓Status is a solid fill. Tinted pastel backgrounds are not part of this system.
✓Nothing is square: every surface and control carries a radius.
✕No emoji. Custom icons are used with icon library support.
✕No gradient on text, and never on two elements in one view.

Color

Four Spunk hues over a near-white ground, inked in slate. Teal leads accents; magenta doubles as out-of-range, which is why alarm states feel like part of the brand rather than an interruption.

Gradient set

Three gradients, in priority order. Primary carries actions, secondary carries emphasis and the primary button's hover end, tertiary is a data accent only — it never sits under white text.

Primary
--gradient-primary · teal → royal · white text only past the royal half
Secondary
--gradient-secondary · violet → magenta · holds white text throughout
Tertiary
--gradient-tertiary · in-range lime → watch · ink text only
Tertiary — cool
--gradient-tertiary-cool · teal → lime · alternate when tertiary sits near status pills

The gradient rule

Pick the one element the screen leads with and give it the gradient. Everything else uses flat color. The primary button is a special case: it shows only the teal→royal half of the track at rest and pans to violet→magenta on hover, so the full four hues are never on screen at once.

Rest — teal → royal
Hover — violet → magenta
Screen Gradient goes on
Dashboard The "Log a test" CTA (--gradient-spunk). The avatar ring is a permitted second use only because the CTA sits in a separate fixed bar.
Parameter history The chart line. The hero card behind it uses the light wash, not the full gradient.
Overview The avatar ring. Mini charts drop to royal blue — twelve gradient sparklines would read as decoration.
Log a test / Settings The primary button.

Type

Three faces with strict jobs. DynaPuff carries the personality, Plus Jakarta Sans carries the interface, Fira Code carries the data.

DynaPuff 400--font-name — the word "Spunk's" and every child-page title. Nowhere else.
Plus Jakarta Sans 500–800--font-sans — labels, body, buttons. Never weight 400.
Fira Code 400–600--font-mono — all numbers, units, ranges, timestamps, eyebrows.

Rules

✓Set font-variant-numeric: tabular-nums on anything a user compares down a column.
✓Units follow the value as a quieter mono span: 22 ppm.
✕Don't set a number in Plus Jakarta Sans, even in a button label like "3 overdue".
✕Don't use DynaPuff for body copy, buttons, or anything under 20px.

Elevation

Two shadows. --shadow-tile lifts white cards off the pearl ground so they read as objects; --shadow-cta is a royal-blue glow reserved for the primary button. A third shadow would flatten the difference.

Motion & states

Motion confirms a touch and nothing else. There are no page transitions, no entrance animations, no bounces.

State Treatment
Press scale(0.98) plus opacity 0.9, over --dur-fast (120ms) --ease-out. Applies to buttons and tiles.
Hover Surface darkens one step (mist → line). Pointer-only; never the sole affordance.
Focus Border becomes --royal. No glow, no outline offset.
Selected Ink fill for chips; white raised thumb with --shadow-segment for segmented controls.
Disabled 40% opacity, shadow removed, cursor default.
Overdue The one state that changes a surface: mist background, dashed border, grey text.
State change 200ms --dur-base ease-out on color and background.

Components

Twelve primitives live in components/core/. Each has a .d.ts for its props and a .prompt.md for when to reach for it. Compose screens from these rather than restyling raw elements.

Patterns

Dashboard: one urgent thing, then the grid

Tiles sit in a two-column grid. Sort by severity — out of range, watch, overdue, in range — and give the single worst parameter the hero variant so it spans the row with a 44px number and a labelled pill. If everything is in range, no hero tile: the grid alone is the good news.

Ranges are one control, not two fields

Anywhere a user sets an ideal min and max, use RangeField: two 84px mono inputs and a two-thumb slider bounded to what a hobbyist test kit can actually report. Thumbs can't cross, typed values clamp to the opposite end, and each parameter declares its own bounds and step (pH 5–9 step 0.1; Nitrate 0–80 step 1; Temperature 65–90 step 1).

Destructive actions confirm in place

Deleting a reading swaps the row's contents for "Delete this reading?" with Cancel and Delete. No dialogs, no toasts — the row you are acting on is the thing that changes.

The primary action is pinned

"Log a test" lives in a bottom bar with a fade from the pearl ground, padded by env(safe-area-inset-bottom). One primary action per screen, full width, 56px.

Charts

A chart here answers one question: is this parameter drifting out of its band? Everything that does not serve that is removed.

Element Treatment
Line 3.5px, round caps and joins. Gradient on the history hero; --royal everywhere else.
Points 5px filled with the reading's status color, 2px white stroke. The latest point is 1px larger.
Ideal band --good (#6DA82E) at 18% opacity, 8px radius. No border.
Axes No axis lines, no vertical gridlines. Mono tick labels only where a value must be read.
Empty "Not enough data in this range" in tertiary text at the chart's height — never a zero line.

Copy

Plain, second person, sentence case. The app is a log, not a coach: it reports what the water is doing and leaves the judgment to the owner.

Write

✓"Log a test" · "No readings yet" · "Test overdue"
✓"Couldn't load your tank data" — errors start with "Couldn't" and name the thing.
✓"Imported 12 readings, skipped 1 row." — say the count.
✓Terse time on tiles (2h, 6d, 3w), full time in lists (Sep 5 · 7:02 AM).

Avoid

✕Exclamation marks, emoji, and cheer ("Nice work!").
✕Alarm language beyond the status word — "Out of range", not "Danger".
✕Title Case in buttons and headings.
✕Calling Spunk "your fish". He has a name.

Checklist before you ship a screen

1Exactly one gradient element, and it's the thing the screen is for.
2Every number is Fira Code and tabular; every unit is a quieter mono span.
3One primary button, full width, in the bottom bar.
4Every tappable thing is at least 44px, and numeric inputs set inputMode="decimal".
5Status colors come from the tokens — deep fills under white text, bright hues for dots.
6Overdue surfaces are mist with a dashed border, not red.
7Copy is sentence case, no emoji, and the empty state says what to do next.
8The layout survives 390px wide with the bottom bar and the safe-area inset.

Using the tokens

Link one stylesheet and reference variables. Do not hardcode hexes, and do not add a token without adding it to tokens/.

<link rel="stylesheet" href="styles.css">

/* styles.css imports, in order: */
tokens/fonts.css       @import of DynaPuff, Plus Jakarta Sans, Fira Code
tokens/colors.css      base hues, gradients, semantic aliases
tokens/typography.css  font stacks and the type scale
tokens/shape.css       radius, spacing, sizes, shadows, motion
.tile {
  background: var(--bg-surface);
  border: 1px solid var(--border-default);
  border-radius: var(--radius-tile);
  box-shadow: var(--shadow-tile);
  padding: var(--space-4);
}
.tile__value {
  font: var(--text-num-lg);
  font-variant-numeric: tabular-nums;
}
.tile__meta { font: var(--text-meta); color: var(--text-tertiary); }
