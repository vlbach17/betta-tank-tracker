# Decisions

Short log of non-obvious decisions made while building this, including things deliberately chosen *not* to do. Append new entries at the bottom, numbered sequentially — decision, date, why.

Foundational architecture (two-table schema, no login/single-user, one-reading-per-test rather than a forced full panel, mobile-first layout) is documented directly in `betta-tank-tracker-spec.md` rather than repeated here.

1. **Deploy to Cloudflare instead of GitHub Pages.** 2026-09-05. The GitHub repo is private, and free GitHub Pages requires a public repo. Cloudflare Pages/Workers serves private repos on the free tier with no plan upgrade needed.

2. **Connect Cloudflare via Git integration rather than the Wrangler CLI.** 2026-09-05. Matches the original "auto-build on push" deployment goal without a GitHub Actions workflow or stored deploy tokens. A CLI-only setup would need manual redeploys or its own CI wiring to get the same behavior.

3. **Deploy target is Cloudflare Workers with static assets, not classic Pages.** 2026-09-05. Not really a choice — Cloudflare's current "Workers & Pages" onboarding now routes new git-connected projects through the Workers-with-static-assets product by default (confirmed by the `*.workers.dev` domain and the dashboard defaulting to `npx wrangler deploy` instead of `wrangler pages deploy`). No repo changes were needed since it still just builds and serves `dist`.

4. **Defer photo import of handwritten logs to v2.** 2026-09-05. Keeps v1 shippable without depending on an Anthropic API key / prepaid balance. The full flow (edge function, review screen, cost notes) is preserved in `betta-tank-tracker-spec.md` under "v2 (future)" instead of being discarded.

5. **Use `vite-plugin-pwa` + `@vite-pwa/assets-generator` instead of hand-writing the manifest and service worker.** 2026-09-05. Generates a correct manifest and an auto-updating, app-shell-precaching service worker, and rasterizes the existing logo SVG into every required icon size (192, 512, maskable, apple-touch) from one source file — avoids manually drawn icons or hand-rolled cache logic.

6. **Approved npm's install-script gate for the `sharp` package rather than avoiding it.** 2026-09-05. npm 11's script-approval gate blocked `sharp`'s postinstall step, which fetches its prebuilt binary and is required for `@vite-pwa/assets-generator` to rasterize the SVG. `sharp` is a widely-used, well-vetted image library, so the script was approved for that one package rather than working around the dependency.

7. **Switched to a branch-based deploy workflow: `dev` for day-to-day work, `master` for production.** 2026-09-05. `master` auto-deploys to the live Cloudflare URL on every push with no approval step; pushing to `dev` only triggers a Cloudflare preview build instead. Chosen over Cloudflare's "manual deployment approval" setting so nothing changes about the git workflow's tooling — just which branch gets pushed to.

8. **Added `wrangler.jsonc` (`name`, `compatibility_date`, `assets.directory: "./dist"`) to the repo.** 2026-09-05. The Cloudflare deploy step runs `npx wrangler versions upload`, which failed with "Missing entry-point to Worker script or to assets directory" because no wrangler config told it where the build output lives. This had been silently relying on the dashboard's zero-config Vite preset for earlier production deploys; it broke on the first `dev`-branch build.

9. **Renamed the app from "Betta Tank Tracker" to "Spunk's Bettabase."** 2026-09-05. Personalizes it after the betta it was built for (Spunk), and sets a naming pattern — "{Name}'s Bettabase" — for if a second tank/fish is ever added (see "Multiple tanks" in `ROADMAP.md`). Left the npm package name (`betta-tank-tracker`), repo name, and Cloudflare Worker name unchanged since renaming those risks breaking the deploy pipeline; only user-facing display strings changed (page title, PWA manifest name/short_name, apple-mobile-web-app-title, in-app header, README heading).

10. **Kept Recharts over the Iridescent design system's pure-SVG `Sparkline` reference component.** 2026-09-06. Recharts already provides tooltip, `ReferenceArea` ideal-band, and axis behavior the app relies on; the design system's `Sparkline.jsx` has no tooltip/hover-value interaction at all. Restyled Recharts' output (gradient stroke on the History hero chart, flat royal elsewhere, larger dots, higher band opacity) instead of introducing a second charting approach.

11. **Adopted the design system's solid-fill treatment for status pills and error/success banners, replacing the old pale-tint style.** 2026-09-06. The Iridescent style guide's non-negotiables state status fills are solid, never tinted — the old `-bg` tokens (e.g. `--color-status-bad-bg`) meant "pale wash"; they now mean "solid pill/banner fill." This changes error-banner tone from a soft tint to a bold solid block (see the new shared `Notice` component).

12. **Collapsed the design system's two near-duplicate brand gradients (`--gradient-cta-track` and `--gradient-spunk`) into one token, `--gradient-cta-track`.** 2026-09-06. Both were 4-stop teal→royal→violet→magenta gradients with slightly different stop positions that could drift out of sync over time. The avatar ring and hero-card wash derive their own angle-specific tokens (`--gradient-avatar-ring`, `--gradient-hero-wash`) from the same brand colors instead of a second named gradient variable.

13. **Installed `@phosphor-icons/react` as an interim icon library rather than adopting the design system's "no icon library, 3 glyphs only" rule as final.** 2026-09-06. The finalized Iridescent style guide specifies exactly 3 hand-drawn glyphs (chevron, trash, kebab) and no icon library; the roadmap's existing plan to add broader icon support (previously scoped as Tabler) took precedence for now. The 3 hand-drawn glyphs stay as bespoke SVG (centralized in a shared `Icon`/`IconButton` component) since they already match the brand; Phosphor fills only net-new icon needs. A fully bespoke SVG set is the intended eventual replacement for Phosphor.

14. **Swapped the font stack from Libre Franklin / Raleway / IBM Plex Mono to Plus Jakarta Sans / Fira Code / DynaPuff, and retired the `--font-heading` token.** 2026-09-06. Matches the Iridescent design system exactly. Iridescent doesn't use a second UI family for headings — it uses heavier weights of the body sans-serif (Plus Jakarta Sans) plus a narrow-use display font (DynaPuff) reserved for the wordmark and lowercase page titles, so `--font-heading` had no replacement token and every call site was reconciled individually rather than mechanically renamed. Also disabled Fira Code's code ligatures (`font-variant-ligatures: none`) globally, since a plain numeral like "6.5–7.5" was rendering with a mangled glyph — Fira Code's contextual alternates are meant for code, not plain numeric UI text.

15. **Kept the legacy `favicon.svg` shape unchanged this pass; only its derived PWA icon colors were regenerated.** 2026-09-06. No brand logo exists in the Iridescent design system — only Spunk's photo (used for the new header avatar) and the pre-existing, brand-unrelated favicon shape. Designing a real Spunk-derived app icon is deferred to `ROADMAP.md`'s Someday list rather than attempted as part of a token/component re-skin.

16. **Adopted `NavChips` as Dashboard/Overview/Settings' primary navigation, fully replacing Dashboard's header text links and dropping `BackLink` from Overview and Settings.** 2026-09-06. Matches the Iridescent design system's screens exactly. `BackLink` remains only on LogTest and ParameterHistory, which sit one level deeper than top-level nav. A dedicated usability review of this navigation change was explicitly deferred rather than done as part of the re-skin (see `ROADMAP.md`).

17. **RangeField (the new dual-thumb ideal-range slider) commits to Supabase on drag-release/blur, not on every `onChange` tick, and uses a hybrid bounds table.** 2026-09-06. A slider's `onChange` fires continuously during a drag with no natural blur event, so writing on every tick would spam the database; local edit state still updates live for a responsive UI. Slider min/max/step bounds are hardcoded for the 7 known parameters (pH, Ammonia, Nitrite, Nitrate, KH, GH, Temperature — matching the design system's tuning, minus its stray "Phosphate" demo entry) and fall back to a generic `ideal_min/max ± padding` formula for any future custom parameter.

18. **Darkened the teal stop used specifically in the primary-button gradient (`#14b8c4` → `#0d7d87`), leaving the brand teal untouched everywhere else (avatar ring, chart line).** 2026-09-06. White label text over the button's at-rest (non-hover) state — pure brand teal — measures roughly 2.4:1 contrast, well under WCAG AA's 4.5:1 for normal-size text; the darker teal clears ~4.9:1. The style guide itself flagged this exact tension ("white needs the royal half") and offered darkening the teal stop as one fix. Scoped to the one gradient token that carries text, not the shared `--color-accent`/brand teal used elsewhere without overlaid text.
